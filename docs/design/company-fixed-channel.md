# 公司成员与固定渠道改动方案

已实现，待实际 New API 和浏览器流程验收。本文记录开户、积分分配、固定渠道、数据库迁移和 Lumi 画幅转发方案。

## 开户与使用流程

1. 影策平台管理员为客户开通公司并指定首位公司管理员。该账号的全站角色为 `user`，公司成员记录授予其本公司的管理权限。平台管理员通过现有后台向该账号发放影策积分。
2. 公司管理员在「个人设置 → 公司 → 公司成员」查看、开通和停用本公司员工，并从自己的可用积分分配给员工。员工开户时可用积分和冻结积分均为 0。「公司」分组放在「创作」和「渠道与存储」之间，仅对公司管理员显示。
3. 平台管理员在「模型与渠道 → 固定渠道」维护所有公司共用的 New API 地址、协议和模型。此入口放在「渠道与模型」下方，复用现有渠道与模型配置。
4. 客户使用平台提供的公司 New API 账号，按员工创建和分发独立 Key，并在 New API 设置各 Key 的额度和查看用量。公司管理员使用固定渠道生成时，也在自己的影策账号填写一把 Key。
5. 公司成员在「个人设置 → 渠道与存储 → 固定渠道」填写、替换或移除自己的 Key。该入口放在「个人渠道」下方。用户在现有模型选择器选择已启用且有权限使用的固定渠道模型。

## 权限与账号状态

- 平台开通公司和绑定首位管理员在同一事务内完成，绑定前检查账号的全站角色和现有公司归属。公司成员接口使用独立权限检查和请求字段，后端根据登录身份确定公司和角色。成员列表、开户、停用和积分分配均限定在本公司员工范围。个人设置根据后端返回的公司身份显示入口，实际授权以服务端校验为准。
- 员工开户复用现有账号校验和密码处理，固定为启用的普通用户与公司员工。账号、成员记录、零余额积分账户及审计在同一事务写入，开户流程跳过注册赠送积分。新员工建议进入默认用户分组，分组由平台管理员通过现有入口管理。
- 停用前在事务内复核目标仍是本公司的普通员工，同步更新账号状态、撤销登录会话并写入审计。尚未提交上游的后台任务在执行前检查账号状态，停用后按现有失败和积分释放流程收尾。已提交的上游任务按现有流程查询和结算。
- 项目和素材按个人账号归属。员工离职时，客户在影策停用员工账号，并在 New API 撤销对应 Key。

## 积分分配与用量

- 公司管理员在「公司成员」选择一位启用的本公司员工并填写金额。后端从当前管理员的可用余额扣减等额积分并计入员工可用余额，双方冻结余额保持原值。第一版提供管理员向员工的单向分配。
- 复用现有用户积分账户和积分流水。分配操作在同一事务完成成员校验、余额扣减、员工入账、双方流水和审计。按现有整数微积分单位校验正数与金额范围，扣减条件包含可用余额充足。使用唯一业务键关联转出和转入流水，重试时校验原接收人和金额，避免重复分配或超额扣减。
- 钱包流水显示公司分配转入与转出，分配金额独立于平台充值和模型消耗统计。员工的 0 积分规则适用于开户，签到、兑换、充值等现有入口仍按各自的全站策略处理。
- 影策生成任务沿用系统渠道报价、余额校验、冻结、扣费和失败退款规则。当前在影策查看影策积分流水和任务消耗，在公司 New API 账号按 Key 查看上游实际用量。待确定上游消耗与影策积分的换算及核对规则后，再设计影策内的上游用量展示。

现有单账户积分调整接口只适合平台发放或调整余额。公司分配使用专门的双账户事务，双方继续使用自己的积分账户。账本已有可用与冻结余额以及唯一业务引用字段，可支撑成对流水。[积分账户与流水](../../backend/internal/model/models_finance.go) · [平台积分调整](../../backend/internal/repository/finance_redeem.go)

## 固定渠道与凭据

- 复用现有系统渠道和模型结构，用凭据来源字段标记固定渠道使用成员本人 Key。公司资格和现有分组渠道授权同时满足时才显示可用模型，报价沿用成员本人的分组。平台开通时需检查相关分组已获固定渠道授权。目录、报价、直接选模、逻辑路由和任务准入使用一致的授权条件。
- 平台管理员可以在渠道没有平台 Key 时保存配置并手工维护模型。现有上游拉取和测试依赖渠道 Key。第一版采用手工配置，固定渠道的拉取和测试入口置灰并提示需要专用测试凭据。
- 后端按任务所属用户校验成员资格、账号状态、渠道与模型状态，从平台配置读取目标地址和协议并注入用户 Key。缺 Key 时引导配置，服务端拒绝提交。固定渠道仅接受任务所属用户的凭据。现有出站校验继续适用。
- Key 按用户与渠道在后端加密保存，以支持短剧等后台任务。查询仅返回配置状态，密钥字段对任务响应、诊断和日志脱敏。现有系统渠道执行时会重新读取渠道 Key，因此凭据解析需覆盖画布、短剧、使用同一系统渠道的 Agent 生成以及任务恢复入口。[现有渠道解析](../../backend/internal/app/provider.go) · [任务密钥加密](../../backend/internal/app/settings.go)
- 首次向上游提交前，由服务端将该次执行的凭据、目标地址和协议保存到受保护的任务记录中。已提交或结果尚未明确的任务沿用这份记录进行查询、轮询和恢复，避免换 Key、移除 Key 或后台重启后重复生成。新生成重新检查资格并读取当前 Key。上游已撤销旧 Key 时，按现有查询失败或费用待核对流程处理。
- 固定渠道生成走任务队列。通用系统中转和缺少任务所有者的直接调用拒绝固定渠道。

## 数据库迁移

版本 94 新增三张表，并为模型渠道和路由尝试各增加一个字段。

| 数据 | 变更 |
| --- | --- |
| 公司 | 新表，保存公司 ID、名称及时间戳。 |
| 公司成员 | 新表，关联公司和用户，记录公司管理员或员工角色。按公司 ID 建索引，按用户 ID 加唯一约束，每个用户最多归属一家公司。账号状态使用现有用户记录。 |
| 用户渠道凭据 | 新表，按用户 ID 与渠道 ID 建联合唯一约束，保存加密 Key 和更新时间。 |
| 模型渠道 | 新增凭据来源字段，区分平台 Key 和用户 Key。已有渠道迁移后默认沿用原凭据来源。 |
| 积分账户与流水 | 复用现有表和余额字段，增加公司分配转出、转入流水类型，通过现有唯一业务引用关联同一笔分配。 |
| 路由尝试 | 新增加密的提交凭据字段。每次尝试保存本次提交所需凭据，供异步查询和恢复使用。 |

通过版本化迁移覆盖 SQLite 和 PostgreSQL。存量账号的公司关系按实际开通建立，存量渠道保留现有模型配置。实施时同步更新数据库专题文档与 OpenAPI 说明。

## Lumi 视频画幅

在 `scripts/build-lumi-plugin.py` 移除首帧和首尾帧只允许 `adaptive` 或省略画幅的本地预检。固定比例与 `adaptive` 按现有 `ratio` 映射原样转发。协议层没有画幅值时省略该字段，应用入口仍按现有报价规格和默认值生成任务。New API 根据实际模型和模式校验，影策显示上游错误。短剧单段生成继续读取作品画幅。

同步修改 Lumi 设置里「首帧或首尾帧请选择 adaptive」的提示和现有预检测试。从构建源重新生成 manifest、接口说明和 `.yingce-plugin` 包，验收时确认服务加载的是更新后的插件。与首尾帧画幅无关的校验继续适用。[插件构建源](../../scripts/build-lumi-plugin.py) · [Lumi 设置](../../web/src/components/lumi-video-settings.tsx) · [现有预检测试](../../backend/internal/protocol/lumi_ark_video_test.go)

## 实施与验收

1. **迁移与开户。** 验证存量账号、模型渠道的默认行为及新员工 0 积分开户。用两家公司核对成员查询、停用和分配的权限隔离，验证停用撤销既有会话并阻止新的上游提交。
2. **积分分配。** 验证管理员扣减和员工入账同额，双方流水可对应。覆盖余额不足、非法金额、分配与生成并发、重复请求及事务失败，核对账务状态和冻结积分。
3. **固定渠道。** 验证分组授权、缺 Key、无效 Key、员工与管理员各用自己的 Key。核对 New API 用量归属与影策积分结算。验证关闭浏览器后的短剧执行，以及换 Key、移除 Key、后台重启后已提交任务的查询与新任务的凭据使用。
4. **Lumi 画幅。** 用模拟上游验证首帧和首尾帧请求的 `16:9`、`adaptive` 原样送达，协议层空值省略，上游拒绝的原因在影策可见。再通过实际使用的 New API 实例抽测。
